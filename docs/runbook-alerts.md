# Alert Runbook

Operational procedures for handling alerts generated by the monitoring stack.

---

## InstanceDown

**Severity:** Critical

**Description:** A monitored instance has been unreachable for more than 1 minute.

**Steps:**
1. Check if the instance is reachable via ping or SSH
2. Verify the Node Exporter service is running: `systemctl status node_exporter`
3. Check system logs: `journalctl -u node_exporter -n 50`
4. If the host is unreachable — escalate to on-call engineer
5. If Node Exporter crashed — restart it: `systemctl restart node_exporter`

---

## HighCpuUsage

**Severity:** Warning

**Description:** CPU usage has been above 85% for more than 5 minutes.

**Steps:**
1. Identify top processes: `top` or `htop`
2. Check for runaway processes: `ps aux --sort=-%cpu | head -10`
3. Review recent deployments or cron jobs that may have triggered the spike
4. If sustained — consider scaling or investigating the offending process
5. Document findings in the incident ticket

---

## HighMemoryUsage

**Severity:** Warning

**Description:** Memory usage has been above 90% for more than 5 minutes.

**Steps:**
1. Check memory consumption: `free -h`
2. Identify top memory consumers: `ps aux --sort=-%mem | head -10`
3. Check for memory leaks in long-running processes
4. If swap is being used heavily: `swapon --show` and `vmstat -s`
5. Consider restarting the offending service or scaling the instance

---

## DiskSpaceCritical

**Severity:** Critical

**Description:** Disk usage has exceeded 85% on a monitored filesystem.

**Steps:**
1. Identify the full filesystem: `df -h`
2. Find largest directories: `du -sh /* 2>/dev/null | sort -rh | head -20`
3. Check and rotate logs: `journalctl --disk-usage` and `journalctl --vacuum-size=500M`
4. Remove old Docker images if applicable: `docker system prune -a`
5. If disk is critically full — escalate immediately to prevent service disruption

---

## HighNetworkErrors

**Severity:** Warning

**Description:** Network errors exceeding 10/s on a monitored interface.

**Steps:**
1. Identify the affected interface: `ip -s link`
2. Check for packet loss: `ping -c 100 <gateway>`
3. Review interface errors: `ethtool -S <interface>`
4. Check switch/router logs for port errors
5. If hardware related — escalate to network team
